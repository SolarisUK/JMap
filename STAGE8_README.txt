What was wrong in the supplied generator
----------------------------------------
It always wrote boxes around the zone centroids. It did not read zones.geojson.
Its general write function rounded every float to three decimal places, which
would also alter real polygon coordinates if used for the GeoJSON.

The updated generator loads the validated Stage 7 GeoJSON, verifies the five
feature properties against your current schemas.ZONES, checks its source hash,
and copies its bytes directly to stubs/zones.json. Coordinate precision is
preserved. There is no fallback to placeholder boxes.

The project root is resolved from the script path or --root, so the generator
works from both the original root-level entry point and the runbook's scripts
entry point. JSON text writes use UTF-8 explicitly.

Why use --zones-only for this step?
----------------------------------
This refreshes the map payload and handover files without importing the
simulator or baseline-agent modules. Existing non-zone stubs are left in place
and are not represented as checked or regenerated by this run.

The supplied full generator contains a mock LOND forecast curve and mock
explanations. Its agents comparison copies the optimiser's scores and has
agents_is_placeholder=True. Those are examples, not trained-model results.
Their status is kept explicit in the notes/provenance. No new forecasting
accuracy or agent-performance claim is made by this data handover.
